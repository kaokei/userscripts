# 领域文档

本仓库采用 `single-context`（单一上下文）布局：根目录 `GLOSSARY.md` 存放领域术语，`docs/adr/` 存放 ADR（架构决策记录）。

## 探索代码前的读取规则

- 若根目录存在 `GLOSSARY-MAP.md`，先读取该索引，再读取与当前任务相关的词汇表。
- 否则，读取根目录 `GLOSSARY.md`。
- 读取 `docs/adr/` 中与当前改动相关的架构决策记录。
- 若以后采用多上下文布局，同时检查 `src/<context>/docs/adr/` 中的相关决策。

文件或目录不存在时直接继续，不因缺失而中断，也不提前创建空词汇表或空决策记录。`domain-modeling`（领域建模技能）在术语或决策实际确定后按需创建文档。

## 文档布局

```text
/
├── GLOSSARY.md
└── docs/adr/
    └── YYYY-MM-DD-0001-<decision-slug>.md
```

固定词汇表入口保留上述文件名，新增架构决策记录的文件名以日期开头。

## 使用已有术语

工单标题、重构提案、假设和测试名称涉及领域概念时，采用 `GLOSSARY.md` 已定义的名称，避免使用词汇表明确排除的同义词。

若需要的概念尚未收录，先判断是否符合项目现有用语；确有术语缺口时，将其记录为后续领域建模事项。

## 明确决策冲突

提案与现有 ADR 冲突时，应指出对应记录及重新讨论的原因，不静默覆盖已有决策。
